01行业动态旅行+AIPersonal Agent也适合开发

Travelport、Mastercard 等四家跑通 AI Agent 真实订机票：用户在对话里批准一次，付款按这次批准核对，Agent 全程看不到卡号

Travelport、Booked AI、Basis Theory 和 Mastercard 在 11/12 宣布，完成了一笔真实的端到端 AI 订票：Booked AI 的旅行 Agent 通过 Travelport TripServices 拿到一家大型国际航司的实时 NDC 报价；用户在对话里确认航班和票价后，由 Mastercard Agent Pay 用代币化凭证发起付款，真实卡号存放在 Basis Theory 的 PCI 合规保险库里；最后经 Travelport 和航司自己的系统出票。

为什么值得关注这是一条“被授权”的 Agent 订票路径：用户批准的是具体的预订和金额，Mastercard 的 Verifiable Intent 把这次批准和交易绑定，交易内容对不上就不付款，再买别的需要重新批准；航司全程是收款方。和同一天 United 限制未授权 Agent（见 03）放在一起看，航司反对的是 Agent 拿着用户账号代操作，而不是 Agent 订票本身。目前只是一笔演示交易，航司名称没有公开。

对我们有什么用程小帮做代订时，可以参照这条链路设计“用户批准了什么、付款前核对什么”：批准页写明车次／航班和金额，付款前再核对一次，有任何偏差就重新确认；支付凭证不进入模型上下文。国内的支付和出票渠道不同，具体做法需要和支付、供应链团队一起评估。

02官方动态Personal Agent也适合开发

ChatGPT 的 dots 支持自定义规则：每类动作可以设成“直接做／你说了才做／先问我／交给我做”四档

OpenAI 在 11/12（美国时间）通过 ChatGPT 官方 X 账号更新了常驻 Agent dots：回复更快、术语更少、执行更到位，并支持自定义指令。官方文档同时写明了“自定义规则”：用户给某一类动作选择处理方式，分为直接做、用户明确要求时才做、先请求批准、交给用户自己做四档。文档举的例子是：给客户发消息设为先问，删除共享项目文件设为交给用户。

为什么值得关注dots 把“风格偏好”和“动作权限”分开：写作风格、多久汇报一次放在自定义指令里，什么时候可以动手由规则决定。文档还写明：执行可能影响账户或对外发信息的动作前，会先做一次自动审查，对照用户指令、权限、规则和内置安全要求；“让它起草回复”不等于允许它发送；规则不能授予应用权限，也不能跳过必需的确认（例如使用已保存的登录信息）。官方没有给出提速幅度等数字。

对我们有什么用程小帮的权限设计可以参考这套四档动作规则，以及“起草不等于发送”的授权范围：把订票、改签、付款、给酒店发消息等动作逐项列出，先定默认档位，再允许用户在对话里修改。可以和上期的 Nod、授权漂移论文放进同一张对照表。

03行业动态旅行+AIPersonal Agent

United 限制未经授权的第三方 AI Agent 访问官网和 App，旅行社和聚合平台也不能用这类 Agent 代订

美联航在 11/11 发布公告，限制未经授权的第三方个人 AI Agent 或助手访问它的网站、App，以及订票、出票和分销系统，范围也包括通过旅行社和聚合平台间接访问。帮助中心写明：没有获得 United 许可，任何替用户搜索、预订、购买、管理行程或收集信息的 Agent、机器人、浏览器插件或浏览器功能都算未授权；United 目前还没有和任何第三方 Agent 合作；11/11 之前 Agent 已经做的订单不会被取消。

为什么值得关注United 给出三个理由：用户把常旅客账号密码交给 Agent 有泄露风险；Agent 可能造成用户不想要的购买、账户改动或里程使用；自动值机可能违反 FAA 和 DOT 的规定（值机需要本人确认行李里没有违禁品）。TechCrunch 提到，美国银行等机构也在提醒用户不要把密码交给 AI 助手。

对我们有什么用如果程小帮要替用户操作第三方网站，需要先评估渠道方会不会限制 Agent 代操作，优先走官方接口或授权合作。它给用户的安全提示也可以借鉴：做规划时只给 Agent 一般信息，不交出账号密码和证件信息。

04产品旅行+AIPersonal Agent也适合运营

商旅 Agent Otto：过半预订已经从 Claude 和 ChatGPT 里发起，用户通过 MCP 连接器直接订机票、酒店和租车

Otto The Agent 是面向商务出行的 AI 旅行 Agent。它在 11/12 通过 Business Wire 宣布：超过一半的预订现在从 Claude 和 ChatGPT 里开始。用户把 Otto 的 MCP 连接器加进这些助手后，可以在对话里比较实时的航班、酒店和租车选项，确认后预订，也能改签和取消；这些订单会出现在 Otto 账户里，同步到日历，并享有同样的行程异常监控。

为什么值得关注这是旅行服务商“进到通用助手里”的一个具体数据点：下单入口在别人的对话里，账户、偏好、会员和支付方式、售后仍在 Otto 自己手里。官方页面写明，助手未经用户批准不能花钱；任何兼容 MCP 的客户端都可以通过 OAuth 登录接入。“过半”是厂商自己的说法，没有披露订单总量。

对我们有什么用评估把车票、酒店能力做成通用助手里的连接器时，可以参考 Otto 的分工：搜索和下单在助手里完成，账户、订单和异常处理留在自己的系统里。对照 08 里大平台“Agent 带来的订单不到 1%”的说法，这类入口在国内能带来多少量，需要我们自己测。

05公众号 / 播客Personal AgentHarness / Agent 工程也适合开发

Founder Park 转载黄东旭：模型够聪明之后，速度会改变产品形态，比如规划周末出游时当场生成一个能操作的比较界面

PingCAP 联合创始人兼 CTO 黄东旭的文章，Founder Park 在 11/13 转载。他认为开源小模型已经够日常 Agent 工作使用，接下来拉开差距的是速度：判断、调用和试错都快上十倍后，原本扔到后台等待的任务会变成实时交互；Agent 也不必先想出完整方案，可以快速试几轮、看反馈，一步步逼近答案。

为什么值得关注文中有两个可以借鉴的设计。一是分工：强模型先看问题、提出几个办法，执行过程中频繁出现的小判断交给低延迟的选择模型（比如先跑哪条路、遇到某个错误值不值得重试）。二是界面在用的时候生成，他举的例子正是周末出游：聊着聊着想比较几个地方，App 当场生成一个能操作的比较界面。文中引用 Fireworks 自测：一个 30 轮的 Agent 任务从约 1 分钟降到 8 秒。以上是作者观点和厂商数据。

对我们有什么用可以和上期 Airbnb 的组件式回答放在一起看：trip planner 里哪些步骤因为慢只能放在后台（比价、查余票、拼换乘），如果快到能边聊边出，交互可以怎么改。开发可以统计小帮一次任务里有多少次串行的小判断，评估换成低延迟模型的收益。

06产品内容制作+AI

即梦上线“动效工作室”：一段文字生成带配音和配乐的动效视频，适合活动预告、卖点展示和知识科普

字节旗下的即梦在 11/10 上线动效工作室（Motion Studio），主打“用文字描述创意，通过代码编译视觉画面”：先理解意图、规划叙事，再分别生成配音和画面并合成，最后做一次核验。适用场景包括标题开场、动态金句、活动预告、产品卖点展示、概念图解、流程说明和转场特效。

为什么值得关注这类“Vibe 知识”视频正在走红，机器之心引用抖音话题 #Vibe知识大赏 的数据：18.6 万人参与、累计播放 43.8 亿次。机器之心实测一条 60 秒的物理科普用时约 8 分半、消耗 82 积分，画面、配音、配乐一次成型；瑞财经提到，提示词写得太粗风格会失控，写得太细又会压缩模型的编排空间。即梦还预告了面向商品和广告的营销工作室。

对我们有什么用运营可以拿一个出行知识点（比如“候补购票怎么用”）试做一条 60 秒的动效短视频，和现在的制作耗时对比；注意提示词的颗粒度，商业投放前要确认素材版权。

07产品内容制作+AI也适合开发

YouArt Desktop：直接在电脑上操作 After Effects、CapCut 和 Blender 的视频制作 Agent，本地素材和 Slack、Gmail 里的反馈汇总到一张画布

YC 公司 YouArt 在 11/12 上架桌面版，自称“创意团队的 Codex”。它把本地文件和 Slack、Gmail、GitHub 里的上下文拉到同一张画布上，用 computer use 直接操作 After Effects、CapCut 和 Blender，从产品发布视频、爆款翻拍到长视频切片都可以端到端完成；用户可以自带模型 API Key，它会把每个镜头的生成任务路由到最便宜的供应商。

为什么值得关注Product Hunt 11/12 日榜第 2。和只在浏览器里生成片段的工具相比，它的思路是把 Agent 带到素材和剪辑软件所在的电脑上。创始人在评论区说，After Effects 最稳定（特效、遮罩、可编辑关键帧和渲染，都会回读工程文件核验），CapCut 也能用，两者可以在一个任务里串起来。新用户有 50 个免费积分。效果均为厂商自述。

对我们有什么用运营做目的地或活动视频时，可以试它“先在 AE 做动效、再进 CapCut 剪辑导出”的串联流程，看能省多少手工；开发可以留意它用回读工程文件来核验 computer use 结果的做法。

08公众号 / 播客旅行+AIPersonal Agent也适合产品

PhocusWire 汇总旅行公司财报会：个人 AI 助理带来的预订还很少，但 AI 来的流量转化更高

PhocusWire 11/12 的文章，汇总了 Meta Muse、OpenAI dots、Instinct 等个人 AI 助理上线后的第一轮旅行公司财报会。Booking 称，来自大模型和个人助理的引流远低于 Booking.com 间夜量的 1%，最近几周有所加速；Uber 称万圣节那周约 3.2 亿单里，经 Agent 完成的只有 500 单外卖和 4 单打车；Airbnb 称来自 Muse 和 Instinct 的流量很少，预订更少。

为什么值得关注量小但质量高：Tripadvisor 称 AI 带来的流量，Viator 的转化率约为平均的 5 倍，Tripadvisor 约为 2 倍；Hyatt 称经 ChatGPT apps 来的旅客更年轻、旅行花费更高。Booking 认为通用 Agent 更愿意接聚合平台，因为直连 470 万家住宿代价太高。文中还转述了一次实测：给 dots 500 美元预算安排一个下午，它反复联系同一家餐厅、记错饮食偏好、提醒没有发出。

对我们有什么用运营看 AI 渠道时，可以先看转化率和客群，而不是流量规模：给来自 AI 助手的访问单独打标，对比转化率和客单价。产品可以把文中实测暴露的问题（重复联系、记错偏好、漏发提醒）加进小帮的测试用例。

09产品Harness / Agent 工程Personal Agent也适合产品

Plurai Simulation：在 Claude Code 里一条命令给 Agent 搭一个“数字孪生”测试世界，评测看它实际改了什么，而不是它说了什么

Plurai 在 11/12 上架 Product Hunt，拿到当日第 1。它以插件形式运行在 Claude Code、Codex 或 GitHub Copilot 里：读取你的代码仓库，为原样不动的 Agent 重建一个测试世界，包括合成的用户画像和文档，以及模拟的工具、API 和数据库，都跑在不接触生产环境的沙箱里；需要保持真实的部分（比如 RAG）照常在线。

为什么值得关注创始人之前做自动驾驶仿真。他的出发点是：多数 Agent 测试只是让假用户和 Agent 聊天、给对话打分，聊天记录里写着“已退款”，退款真的发生了吗？Plurai 的自动评测检查的是 Agent 对测试世界的状态做了什么改动；会“刁难”的模拟用户把每条流程从简单到极端都走一遍；生产故障可以从出错的那一步重放；每个修复都要先过回归集。“失败率降低 82%”是厂商自述。

对我们有什么用小帮 RSI 迭代的评测可以加一条：检查订单、日历等状态是否真的变了，而不只看回复文字。可以先挑改签、退票两条流程，用模拟工具和模拟用户搭一个小测试世界，跑通后再决定要不要引入这类工具。

10论文Harness / Agent 工程Personal Agent

论文：工具超时后，Agent 不知道上一步到底成没成功，先找证据判断状态，再决定补做哪些步骤，避免重复下单

10/30 的 arXiv 论文（作者来自 Accentrust、佐治亚理工等），11/13 进入 Hugging Face Daily Papers。它研究一个常见情况：工具超时后，一个动作可能失败了、已经提交了，或者还在处理中，而流程里的其他步骤已经完成。重跑整个流程可能重复产生不可撤销的效果，直接停下又会漏掉该做的事。论文的做法是：根据用户已批准的事项、服务方的能力（比如是否支持幂等）和公开可查的证据，推断当前可能处在哪些状态，只做能安全完成的剩余步骤。

为什么值得关注它把“任务确实完成”和“依据公开证据可以安全收尾”分开记录，判断不了的结果明确标为未知或转交人工，不假装成功。在作者构造的 19 类任务、58 组配对实验里，给模型提供规划建议时确认完成 30 个，只给证据提示时只有 9 个。实验规模小、任务是合成的，HF 上只有 2 赞，结论需要谨慎看。

对我们有什么用小帮的下单、出票、改签这类不可撤销操作遇到超时，可以借这个思路：先查订单状态再决定是否重试，结果不明时明确告诉用户“状态未知”并转人工。开发可以先检查现有写操作工具是否都带幂等键或可查询的订单号。
